# Governance Portal v1.0.0-alpha.3.0

## Ziel

Diese Iteration führt das metadata-gesteuerte Application Framework ein. Die bestehenden SharePoint-Konfigurationslisten werden beim Start in lokale, ausschließlich für die UI verwendete Collections geladen. Navigation, Objektübersichten, Formularvorschau und Validierungsübersicht basieren damit nicht mehr auf fest verdrahteten Bildschirmdefinitionen.

## Implementiert

- Laden von PageDefinitions, NavigationDefinitions und ObjectTypes
- Laden von FormDefinitions, FormFieldDefinitions und FieldDefinitions
- Laden von ValidationDefinitions, BusinessRuleDefinitions und AppSettings
- Fallback-Navigation, falls die Konfigurationslisten leer oder nicht verfügbar sind
- Framework-Dashboard mit Kennzahlen
- metadata-gesteuerte Navigation
- Objektkatalog mit Quellliste und Feldanzahl
- generische Metadatenansichten für Seiten, Felder, Formulare und Validierungen
- Editor-Bootstrap für den Modus `New`
- Formularfeldvorschau aus FormFieldDefinitions und FieldDefinitions
- Refresh-Aktion für zentrale Metadatenquellen
- sichtbarer Datenfehler- und Aktualisierungsstatus

## Architekturentscheidung

Power Apps unterstützt keine echte dynamische Control Factory, die beliebige Controls zur Laufzeit erzeugt. Das Framework verwendet deshalb einen kontrollierten metadata-driven Ansatz:

1. Metadaten bestimmen Navigation, Sichtbarkeit, Reihenfolge, Labels und Feldzuordnung.
2. Generische Galleries stellen Objekt- und Felddefinitionen dar.
3. Reale Eingabesteuerelemente werden in folgenden Iterationen als wiederverwendbare Feld-Renderer nach ControlType ergänzt.
4. CRUD bleibt je SharePoint-Datenquelle typisiert, wird aber über gemeinsame Commands und Mapping-Konventionen vereinheitlicht.

## Smoke-Test

1. Solution bauen und in DEV importieren.
2. App öffnen und `App.OnStart` ausführen.
3. Prüfen, dass im Footer `1.0.0-alpha.3.0` erscheint.
4. Dashboard-Karten auf plausible Werte prüfen.
5. Navigation aus NavigationDefinitions prüfen.
6. Objektmodul öffnen und Objektdefinition auswählen.
7. Metadatenseiten `fields`, `forms`, `validation` und `pages` über Dashboard-Karten öffnen.
8. In einem Objektmodul `Neu` wählen.
9. Prüfen, dass Editor-Titel und Formularfelder aus den Metadaten erscheinen.
10. `Aktualisieren` ausführen und Zeitstempel im Footer prüfen.
11. Responsive Verhalten unterhalb von 900 px prüfen.
12. App Checker und Build ohne blockierende Fehler abschließen.

## Noch nicht enthalten

- produktive Eingabecontrols pro ControlType
- Patch/SubmitForm-Logik
- rollenbasierte Navigation
- Auswertung von VisibleIf, EnabledIf und RequiredIf
- generischer Lookup-Resolver
- CRUD für alle Governance-Objekte
