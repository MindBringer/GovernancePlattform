# Iteration v1.0.0-alpha.2 – Application Foundation

## Ziel

Diese Iteration etabliert das technische Grundgerüst der Canvas-App. Sie enthält noch keinen fachlichen CRUD-Workflow.

## Enthalten

- zentrale Initialisierung über `App.OnStart`
- globale App-, Benutzer-, Umgebungs- und Busy-Zustände
- zentrale Theme- und Layoutwerte
- initiale Navigationscollection für die Governance-Objekte
- responsive Shell mit Header, Navigation, Workspace, Footer und Busy-Overlay
- PAC-Buildskripte für Canvas-App und Solution

## Technische Entscheidung

Die Foundation verwendet ausschließlich den bereits im Canvas-Paket vorhandenen Control-Typ `groupContainer`. Dadurch bleibt die erste Quellcodeänderung klein und minimiert Risiken durch fehlende Control Templates im eingestellten `*.fx.yaml`-Format.

Visuelle Controls, Navigationselemente und wiederverwendbare Komponenten folgen nach einem erfolgreichen Pack-, Import- und Smoke-Test dieser Struktur.

## Betroffene Dateien

```text
powerplatform/canvas-editable/GovernancePortal/Src/App.fx.yaml
```

## Validierung

Im Repository-Stamm:

```powershell
pwsh ./powerplatform/scripts/Pack-Canvas.ps1
pwsh ./powerplatform/scripts/Pack-Solution.ps1
```

Alternativ vollständig:

```powershell
pwsh ./powerplatform/scripts/Build.ps1
```

## Smoke-Test in DEV

- App öffnet ohne Formel- oder Ladefehler.
- Headerbereich ist oben sichtbar.
- Navigationsbereich wechselt bei kleiner Breite von 248 auf 72 Pixel.
- Workspace nutzt die verbleibende Breite.
- Footer bleibt am unteren Rand.
- Busy-Overlay ist nach erfolgreichem `OnStart` ausgeblendet.
- `colNavigation` enthält zwölf Einträge.
- `gblAppVersion` entspricht `1.0.0-alpha.2`.

## Definition of Done

- `pac canvas pack` erfolgreich
- `pac solution pack` erfolgreich
- Import in DEV erfolgreich
- App startet ohne App-Checker-Fehler
- Desktop- und schmale Browserbreite getestet
- Ergebnis dokumentiert und committed
