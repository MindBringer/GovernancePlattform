Governance Developer Companion

Git-, Power-Platform-, Build-, Deploy- und Release-Workflow.

Lade Status …

1 · Repository

Pull wird nur bei sauberem Arbeitsverzeichnis ausgeführt.

2 · Prüfen

Provider-Sync, Canvas-Pack, Referenzprüfung und Solution-Pack.

3 · Studio Sync · DEV → Git

Führt PAC-Prüfung, DEV-Auswahl, Solution-Export, Unpack, Canvas-Sync und Git-Diff in einem kontrollierten Ablauf aus.

Danach: Diff prüfen und anschließend Deploy to DEV ausführen.

4 · Deploy to DEV · Git → Power Apps

Führt Repository-Audit, vollständigen Build, versionsgenaue Paketauswahl, Solution-Import und --publish-changes aus.

Ergebnis: Die Canvas-App ist direkt in DEV testbar. Kein manueller Solution-Import und kein separates Publish All erforderlich.

5 · PAC-Einzelaktionen

Erweiterte Einzelaktionen anzeigen

Publish All ist optional und veröffentlicht sämtliche ausstehenden Anpassungen der Zielumgebung.

6 · Vollständiger Release

Erst nach erfolgreichem Deploy to DEV und manuellem Smoke-Test verwenden.
